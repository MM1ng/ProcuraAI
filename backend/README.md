# Backend / 后端

FastAPI service for Enterprise Procurement Agent.

Enterprise Procurement Agent 的 FastAPI 后端服务。

## Setup / 启动方式

```powershell
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m app.scripts.generate_products
python -m app.scripts.seed_db
python -m app.scripts.ingest_products
python -m app.scripts.run_mock_evaluation
uvicorn main:app --reload --port 8000
```

## Tests / 测试

```powershell
cd backend
pytest
```

## Main Endpoints / 主要接口

- `GET /health` - Health check / 健康检查
- `GET /api/products` - List products / 商品列表
- `POST /api/chat` - Chat with procurement agent / 与采购智能体对话
- `GET /api/llm/status` - LLM status / 大模型状态
- `POST /api/llm/test` - Test LLM connection / 测试大模型连接
- `POST /api/procurement/plan` - Create procurement plan / 创建采购方案
- `POST /api/orders` - Create order / 创建订单
- `POST /api/payments/create-checkout-session` - Create checkout session / 创建支付会话
- `GET /api/payments/status` - Payment status / 支付状态
- `GET /api/observability/summary` - Observability summary / 可观测性汇总
- `GET /api/evaluation/summary` - Evaluation summary / 评估汇总
- `POST /api/evaluation/run-agent` - Run agent evaluation / 运行智能体评估
- `GET /api/history` - List history / 历史记录列表
- `GET /api/history/{id}` - Get history record / 获取单条历史记录
- `POST /api/history` - Save history record / 保存历史记录
- `DELETE /api/history/{id}` - Delete history record / 删除历史记录
- `POST /api/chat/optimize` - Optimize current plan / 优化当前方案
- `POST /api/export/excel` - Export Excel file / 导出 Excel

The default path uses CSV and JSON fallback files so the demo works without
Alibaba Cloud, OpenAI, Stripe, Langfuse, Ragas, or MLflow credentials.

默认流程使用 CSV 和 JSON 兜底数据，因此即使没有阿里云、OpenAI、Stripe、
Langfuse、Ragas 或 MLflow 凭证，演示也可以运行。

## Vector RAG Ingest / 向量 RAG 数据导入

`python -m app.scripts.ingest_products` builds both retrieval layers:

`python -m app.scripts.ingest_products` 会构建两层检索数据：

- local Chroma collections under `data/chroma/` for products, procurement
  policies, and supplier profiles
- `data/chroma/` 下的本地 Chroma 集合，用于商品、采购政策和供应商画像
- ignored JSON fallback index at `data/retrieval_index.json`
- 被 Git 忽略的 JSON 兜底索引：`data/retrieval_index.json`

By default, Chroma uses Alibaba Cloud Bailian `text-embedding-v4` embeddings
with 1024 dimensions.

默认情况下，Chroma 使用阿里云百炼 `text-embedding-v4` 嵌入模型，向量维度为
1024。

Set `DASHSCOPE_API_KEY` before ingesting to build the index with the real
model. If the key is missing or the embedding API is unavailable, the backend
falls back to deterministic local hash embeddings with the same configured
dimension so the demo still runs.

导入前设置 `DASHSCOPE_API_KEY`，即可用真实模型构建索引。如果缺少 key 或嵌入
API 不可用，后端会回退到确定性的本地 hash embedding，并保持相同配置维度，确保
演示仍能运行。

After changing `EMBEDDING_MODEL` or `EMBEDDING_DIMENSION`, rebuild the Chroma
collections with `python -m app.scripts.ingest_products`; vectors generated by
different dimensions cannot be mixed in the same collection.

修改 `EMBEDDING_MODEL` 或 `EMBEDDING_DIMENSION` 后，需要重新运行
`python -m app.scripts.ingest_products` 构建 Chroma 集合；不同维度生成的向量不能
混在同一个集合中。

`POST /api/chat` adds optional `retrieval_evidence` while preserving the
existing `recommended_plan`, `plan_options`, and `selected_plan_id` response
fields.

`POST /api/chat` 会在保留 `recommended_plan`、`plan_options` 和
`selected_plan_id` 等响应字段的同时，额外返回可选的 `retrieval_evidence`。

## Compare Plans Response / 多方案对比响应

`POST /api/chat` keeps the v1.0-compatible `recommended_plan` field and adds
multi-plan options for v2:

`POST /api/chat` 保留兼容 v1.0 的 `recommended_plan` 字段，并为 v2 添加多方案选项：

```json
{
  "recommended_plan": {},
  "selected_plan_id": "plan_a",
  "plan_options": [
    {"id": "plan_a", "name": "Plan A", "strategy": "cost_optimized"},
    {"id": "plan_b", "name": "Plan B", "strategy": "balanced"},
    {"id": "plan_c", "name": "Plan C", "strategy": "premium"}
  ]
}
```

`plan_b` is preferred when it is within budget. If it exceeds the user's budget
and another option is budget-safe, the backend selects the lowest-cost
within-budget option as `recommended_plan`. The frontend can switch to another
option without calling a new endpoint.

如果 `plan_b` 在预算内，系统会优先选择它。如果它超出用户预算，但其他方案没有超
预算，后端会选择预算内成本最低的方案作为 `recommended_plan`。前端可以在不同方
案之间切换，不需要再次调用接口。

## Quick Optimization API / 快速优化接口

`POST /api/chat/optimize` preserves the `ChatResponse` contract while revising
the current selected plan from the latest parsed intent and plan context.

`POST /api/chat/optimize` 会保持 `ChatResponse` 响应结构，同时基于最新解析意图和
方案上下文修改当前选中的采购方案。

Supported `action` values:

支持的 `action` 值：

- `make_cheaper` - Make the plan cheaper / 降低成本
- `improve_quality` - Improve product quality / 提高质量
- `faster_delivery` - Prefer faster delivery / 更快配送
- `prefer_dell` - Prefer Dell products / 优先 Dell 品牌
- `regenerate` - Regenerate the plan / 重新生成方案

Example / 示例：

```powershell
Invoke-RestMethod http://localhost:8000/api/chat/optimize `
  -Method Post `
  -ContentType "application/json" `
  -Body '{
    "action": "prefer_dell",
    "session_id": "demo-session-001",
    "language": "en",
    "parsed_intent": {"categories": ["Docking Station"], "people_count": 5},
    "current_plan": {"items": [], "total_amount": 0}
  }'
```

The response includes updated `recommended_plan`, `plan_options`, and
`selected_plan_id`.

响应会包含更新后的 `recommended_plan`、`plan_options` 和 `selected_plan_id`。

## Excel Export API / Excel 导出接口

`POST /api/export/excel` returns an `.xlsx` file for the selected plan.

`POST /api/export/excel` 会为选中的采购方案返回 `.xlsx` 文件。

```powershell
Invoke-WebRequest http://localhost:8000/api/export/excel `
  -Method Post `
  -ContentType "application/json" `
  -Body '{"plan":{"items":[],"total_amount":0}}' `
  -OutFile procurement_plan.xlsx
```

The workbook includes product, category, brand, supplier, quantity, unit price,
subtotal, rating, stock, delivery days, selection reason, and total cost.

工作簿包含商品、类别、品牌、供应商、数量、单价、小计、评分、库存、配送天数、选
择原因和总成本。

## Procurement History API / 采购历史接口

The v2 branch adds a lightweight local history store backed by
`data/procurement_history.json`. The file is ignored by Git because it contains
local demo/session data.

v2 分支增加了一个轻量级本地历史记录存储，数据文件是
`data/procurement_history.json`。该文件包含本地演示/会话数据，因此被 Git 忽略。

Create a history record:

创建历史记录：

```powershell
Invoke-RestMethod http://localhost:8000/api/history `
  -Method Post `
  -ContentType "application/json" `
  -Body '{
    "original_request": "Buy monitors for a new office",
    "parsed_intent": {"categories": ["Monitor"]},
    "procurement_plan": {"items": [], "total_amount": 0},
    "trace": {"trace_id": "trace-demo"},
    "reasoning_summary": "Saved procurement plan"
  }'
```

List, restore, and delete:

查询、恢复和删除：

```text
GET    /api/history
GET    /api/history/{id}
DELETE /api/history/{id}
```

## Category Normalization / 类别标准化

The intent parser normalizes requested categories against categories loaded
from `data/products.csv`. It supports exact matches, case-insensitive matches,
stable multilingual aliases, conservative similarity, and optional LLM category
selection constrained to the catalog's allowed categories.

意图解析器会根据 `data/products.csv` 中的商品类别，对用户请求中的类别进行标准化。
它支持精确匹配、大小写不敏感匹配、稳定的多语言别名、保守相似度匹配，以及可选
的大模型类别选择；大模型选择会被限制在目录允许的类别范围内。

The parsed intent includes `category_normalization` trace entries:

解析后的意图会包含 `category_normalization` 跟踪信息：

```json
{
  "original_category": "显示器",
  "normalized_category": "Monitor",
  "normalization_method": "alias",
  "allowed_categories": ["Laptop", "Monitor", "Keyboard"],
  "warning": null
}
```

If confidence is low, the parser preserves the original category and adds a
warning instead of forcing a bad match.

如果置信度较低，解析器会保留原始类别并添加 warning，而不是强行匹配到错误类别。

## Connect Alibaba Cloud qwen-turbo With LangChain Tongyi / 连接阿里云 qwen-turbo 与 LangChain Tongyi

Install dependencies:

安装依赖：

```powershell
cd backend
pip install -r requirements.txt
```

Configure `backend/.env` or the project root `.env`:

配置 `backend/.env` 或项目根目录 `.env`：

```text
LLM_PROVIDER=tongyi
USE_MOCK_LLM=false
DASHSCOPE_API_KEY=your_alibaba_cloud_bailian_api_key
QWEN_MODEL=qwen-turbo
QWEN_TOP_P=0.8
QWEN_MAX_TOKENS=2000
```

Test qwen-turbo:

测试 qwen-turbo：

```powershell
python -m app.scripts.test_qwen_call
```

Start the backend:

启动后端：

```powershell
uvicorn main:app --reload --port 8000
```

Check the LLM endpoints:

检查大模型接口：

```text
GET http://localhost:8000/api/llm/status
POST http://localhost:8000/api/llm/test
```

Use this AI Chat prompt:

可以在 AI Chat 中使用这个提示词：

```text
We need to buy equipment for 20 interns. Budget is under $3000. Each person needs a keyboard, mouse and headset. Prefer high rating and delivery within 5 days.
```

Confirm `/api/chat` returns:

确认 `/api/chat` 返回：

```json
{
  "model_provider": "tongyi",
  "model_name": "qwen-turbo",
  "used_mock_llm": false
}
```

`USE_MOCK_LLM=true` does not call qwen-turbo. Missing `DASHSCOPE_API_KEY` also
uses mock fallback. Never commit `.env` to GitHub. `qwen-turbo` is the default
model. If `used_mock_llm=true`, the response did not come from a real
qwen-turbo call.

`USE_MOCK_LLM=true` 时不会调用 qwen-turbo。缺少 `DASHSCOPE_API_KEY` 时也会使用
mock 兜底。不要把 `.env` 提交到 GitHub。`qwen-turbo` 是默认模型。如果返回
`used_mock_llm=true`，说明响应不是来自真实 qwen-turbo 调用。
